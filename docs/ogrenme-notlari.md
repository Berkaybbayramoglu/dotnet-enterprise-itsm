# ITSM Projesi Öğrenme ve Geliştirme Notları

## Faz 8: Dashboard, Raporlama, Arama & Filtreleme, Knowledge Base
**Kavram:** Entity Framework Core In-Memory Testleri ve `IQueryable` Davranış Farklılıkları
**Basit Açıklama:** Unit testlerde kullanılan In-Memory provider, SQL'e dönüştürülen LINQ sorgularını (örneğin `.ToLower().Contains()`) client-side (bellekte) çalıştırır. Eğer veritabanında "required" (zorunlu) ilişkiler tanımlandıysa (örneğin foreign key olan bir alan nullable değilse), EF Core bu ilişkiyi `INNER JOIN` olarak algılar. Test verisi oluştururken ilişkili entity'leri (Category, Type, Priority) DB'ye eklemezseniz, In-Memory testlerde dahi `Include` veya Navigation Property sorguları (INNER JOIN nedeniyle) ana kaydı getirmez ve testler gizlice başarısız olur.
**Projede Nerede:** `ReportServiceTests.cs` (ExportTicketsToCsvAsync) ve `TicketService.cs` (SearchTicketsAsync)
**Mentor Sorarsa Cevabın:** "Raporlama servislerini test ederken In-Memory veritabanının required (zorunlu) foreign key'ler için INNER JOIN mantığında çalıştığını fark ettim. Test ortamında Ticket oluştururken Category, Type, Priority gibi zorunlu ilişkili tabloları mock olarak doldurmadığımız için `Include` yapıldığında kayıtlar eşleşmiyor ve filtreye takılıyordu. Test verilerini (Category, Type, vb.) context'e ekleyerek bu sorunu çözdüm ve `NullReferenceException`'ları engelledim. Ayrıca frontend tarafında API entegrasyonu için Fetch API kullanarak `api.js` wrapper class'ı oluşturdum."


## Faz 8: Frontend A11y & Readability (WCAG, SonarQube)
**Kavram:** Web Accessibility (a11y), WCAG Temelleri, Semantik Butonlar ve Klavye Navigasyonu
**Basit Açıklama:** Ön yüz geliştirmelerinde tıklanabilir öğeler için (aksiyon veya JavaScript fonksiyonu çağıranlar) `<a href="#">` veya `onclick` event'ine sahip `<span>`/`<div>` gibi non-native (semantik olmayan) etiketler kullanmak erişilebilirliği ve ekran okuyucu (screen reader) deneyimini bozar. Ekran okuyucular anchor etiketlerini sayfa değişimi veya içi boş link olarak okurken, native `<button>` elementlerini doğrudan "Düğme" olarak tanır ve Space/Enter tuşlarıyla yerleşik (built-in) klavye olaylarını (keydown/keyup) yönetir. Input elementleri her zaman `<label for="id">` veya `aria-label` ile birleştirilmeli, boş başlıklar (`<h2></h2>`) DOM'da bulunmamalıdır. Ayrıca modern JavaScript'te global regex (`/g`) ile `String#replace` kullanmak yerine `String#replaceAll` kullanmak kodun okunabilirliğini artırır.
**Projede Nerede:** `wwwroot` altındaki tüm HTML dosyaları (`tickets.html`, `kb.html`, `dashboard.html`) ve `api.js` (`escapeHtml` regex kullanımı vb.)
**Mentor Sorarsa Cevabın:** "Frontend sayfalarımızda aksiyon gerçekleştiren (örneğin Logout yapan) HTML öğelerini `<a href="#">` yerine CSS ile şekillendirilmiş semantik `<button type="button">` elementleriyle değiştirdim. Böylece ekran okuyuculara ve sadece klavye kullanan kişilere (tab navigation) tam destek sağladık. Form elemanlarında erişilebilirlik (aria-label) geliştirmeleri yaptım ve JavaScript kodlarımızdaki karmaşık regex değiş tokuşlarını modern `replaceAll` metoduna geçirerek 'Code Smell' hatalarını temizledim."

## Faz 8: Konfigürasyon Senkronizasyonu (Single Source of Truth)
**Kavram:** Config Drift (Yapılandırma Kayması), Single Source of Truth (Tek Kaynak Doğruluğu) ve Port Sözleşmeleri
**Basit Açıklama:** Büyük projelerde veritabanı bağlantı adresi (connection string) veya API URL'i gibi kritik yapılandırmalar birden fazla yerde hardcode edilirse, zamanla birisi güncellendiğinde diğeri unutulur; buna *Config Drift* denir. `ItsToolDbContextFactory`'nin design-time connection string'i manuel yazıldığında API tarafındaki `appsettings.json`'dan farklı kalabilir. Bu yüzden tüm veriler tek bir kaynaktan (`appsettings.json`) beslenmelidir (Single Source of Truth). Ayrıca Web projelerinin Backend API'ye istek yaparken kullandığı port, Backend'in `launchSettings.json` içindeki `applicationUrl` ayarıyla ve `appsettings.json` içindeki `Cors:AllowedOrigins` listesiyle kesinlikle eşleşmelidir.
**Projede Nerede:** `ItsToolDbContextFactory.cs`, `api.js`, API `appsettings.json` ve `launchSettings.json`
**Mentor Sorarsa Cevabın:** "Çalışma zamanında connection string uyuşmazlığından ve port sorunlarından kaçınmak için `ItsToolDbContextFactory` sınıfını refactor ettim; artık connection string'i hardcoded olarak değil, dinamik olarak `ItsTool.API` içindeki `appsettings.json` dosyasından okuyor. Ayrıca frontend API istek URL'ini API'nin `launchSettings.json` portuyla tam hizaladım ve CORS izinlerini doğruladım."
